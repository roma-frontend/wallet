## 1. 🐞 АУДИТ БАГОВ И ПРОБЛЕМ

### Критические функциональные баги
1.  **[CRITICAL] Переключение Sign In / Sign Up не работает.**
    -   *Симптом:* При клике на кнопку «Ստեղծել» (Create) форма остается в режиме входа. Поле «Имя» не появляется, заголовок не меняется.
    -   *Причина:* В `login/page.tsx` состояние `flow` переключается корректно, но визуально DOM не обновляется из-за рассинхронизации или кэширования. Возможно, проблема в том, что `error` state сбрасывается, но re-render не триггерится для условного рендеринга поля имени.
    -   *Fix:* Проверить зависимость `useEffect` или убедиться, что `key` на форме меняется при смене `flow` для принудительного ре-маунта.

2.  **[HIGH] Ошибка валидации показывается на экране регистрации.**
    -   *Симптом:* После неудачного логина сообщение «Սխալ էլ. փոստ կամ գաղտնաբառ» висит даже после перехода в режим регистрации (если бы он работал).
    -   *Fix:* Убедиться, что `setError(null)` вызывается синхронно и эффективно внутри `switchFlow()`.

3.  **[MEDIUM] Консольные ошибки отсутствуют, но есть визуальные артефакты.**
    -   На скриншотах виден значок «N» (Next.js Dev Tools) в продакшн-подобном интерфейсе. Убедитесь, что `devIndicators` отключены в `next.config.ts` для staging/preview.

### Визуальные баги и Accessibility
4.  **[A11Y] Низкий контраст вторичного текста.**
    -   Светло-серый текст (`text-muted-foreground`) на темном фоне имеет контраст ~4:1. Для мелкого текста (12px) это ниже WCAG AA (4.5:1).
    -   *Fix:* Увеличить яркость `--muted-foreground` в темной теме до `oklch(0.80 ...)`.

5.  **[VISUAL] Неоднозначная кнопка Submit.**
    -   Кнопка говорит «Մուտք» (Вход) даже в режиме регистрации. Пользователь не понимает, регистрируется он или входит.
    -   *Fix:* Использовать тернарный оператор: `isSignUp ? t.auth.signUp : t.auth.signIn`.

6.  **[VISUAL] Placeholder вместо Label.**
    -   В поле «Name» (когда оно появится) placeholder «Բարի վերադարձ» (Welcome back) абсолютно неуместен для поля ввода имени.
    -   *Fix:* Placeholder должен быть `t.auth.namePlaceholder` («Ձեր անունը»).

7.  **[UX] Отсутствие индикатора загрузки при ошибке.**
    -   Если сеть медленная, пользователь не видит feedback между нажатием и появлением ошибки.

## 2. 🧐 ДИЗАЙН-РЕВЬЮ

### Визуальная иерархия
-   **Плюс:** Четкое разделение на Login/Signup через карточку. Градиентный фон создает глубину.
-   **Минус:** Кнопка «Создать» (Switch flow) выглядит как второстепенное действие, но является ключевой для новых пользователей. Она слишком мала и расположена под разделителем.

### Типографика и Spacing
-   **Шрифты:** Noto Sans Armenian + Geist Mono — отличный выбор для финтех-продукта с поддержкой армянского.
-   **Ритм:** Используется 4px сетка. Отступы консистентны (`space-y-4`, `gap-2`).
-   **Проблема:** Заголовки `h1` и `h2` слишком близки по размеру на мобильных. H1 (Logo) и H2 (Form Title) конкурируют за внимание.

### Цветовая система
-   **OKLCH:** Использование OKLCH — это передовой уровень (тренд 2025+). Позволяет перцептивно равномерные градиенты.
-   **Семантика:** Токены `--primary`, `--destructive`, `--success` реализованы правильно.
-   **Accent Themes:** Поддержка 6 акцентных цветов (emerald, ocean, violet...) — мощный ход для персонализации.

### Motion
-   **View Transitions API:** Реализован для баланса (`balance-hero`). Это premium-фича.
-   **AnimatedNumber:** Плавное изменение цифр создает ощущение «живого» приложения.
-   **Недостаток:** Переход между Login/Signup резкий. Нет анимации смены контента (height/morph).

## 3. 💡 КРЕАТИВНЫЕ И УМНЫЕ РЕШЕНИЯ

### 3 Неочевидных UX-улучшения
1.  **Contextual Greeting based on Time + Weather (Micro-personalization):**
    -   Вместо статического «Բարի վերադարձ», используйте динамическое приветствие, которое уже есть в коде (`greeting()`), но вынесите его на экран входа. «Բարի երեկո, Արմեն» (если имя известно из cookie/localStorage) создает мгновенную связь.

2.  **Smart Input Masking for Amounts:**
    -   В формах транзакций используйте автоматическое форматирование чисел *во время ввода* (например, `1000` -> `1,000`), но храните raw value. Это снижает когнитивную нагрузку при чтении больших сумм.

3.  **Haptic Feedback (Mobile Web):**
    -   Добавьте `navigator.vibrate(10)` при успешном добавлении транзакции или переключении таба. Тактильная отдача превращает веб-приложение в нативное.

### Референсы топ-продуктов
-   **Linear:** Обратите внимание на их *Command Palette* (у вас она есть!). Сделайте её более заметной на экране входа (например, подсказка «Нажмите ⌘K для быстрого входа»).
-   **Stripe Dashboard:** Их использование *subtle borders* и *shadows* вместо жестких линий. Ваши карточки уже используют `card-modern`, но на LoginPage карточка слишком «плотная». Добавьте больше воздуха внутрь.
-   **Raycast:** Их подход к *onboarding*. Вместо модального окна (которое у вас есть), попробуйте интерактивный туториал прямо в интерфейсе (Spotlight effect).

### 2 Смелых дизайн-решения
1.  **Glassmorphic Login Card with Dynamic Blur:**
    -   Сделайте карточку входа полупрозрачной (`backdrop-blur-xl bg-card/40`), чтобы градиентный фон просвечивал. Это создаст эффект «парения» и современности.

2.  **AI-Powered Onboarding Preview:**
    -   На экране регистрации покажите *анимированный превью* дашборда, который заполняется демо-данными в реальном времени. Пользователь увидит ценность продукта *до* регистрации.

## 4. 🚀 МОДНОСТЬ И СОВРЕМЕННОСТЬ (2025-2026)

### Соответствие трендам
-   ✅ **OKLCH Colors:** Вы уже используете. Это топ-1% проектов.
-   ✅ **Variable Fonts:** Noto Sans + Geist. Отлично.
-   ✅ **Dark Mode OLED-ready:** Ваш `--background: oklch(0.17 ...)` достаточно темный, но не чистый черный. Это правильно для предотвращения смазывания на OLED.
-   ✅ **AI Integration:** AI Assistant и Insights встроены органично.

### Что устарело / Требует замены
-   ❌ **Standard Modals for Onboarding:** Модальные окна для онбординга воспринимаются как «барьер». Тренд — *Progressive Disclosure* или *Inline Onboarding*.
-   ❌ **Static Icons:** Lucide — отлично, но добавьте микро-анимации при hover (scale, rotate). Статичные иконки выглядят мертво.
-   ❌ **Password Visibility Toggle Icon:** Глаз/Глаз-зачеркнутый — стандарт, но скучно. Попробуйте плавную анимацию иконки или текстовую метку «Show/Hide» для лучшей доступности.

### Применение современных техник
-   **Variable Fonts:** Используйте `font-variation-settings` для анимации веса шрифта при наведении на кнопки.
-   **Micro-interactions:** Добавьте `spring` анимации (Motion library) для появления элементов списка транзакций. Staggered children создают премиальное ощущение.
-   **OLED Dark Theme:** Убедитесь, что в настройках есть опция «Pure Black» для OLED экранов (многие пользователи просят это).

### Пример кода: Фикс переключения форм (Login Page)

```tsx
// src/app/login/page.tsx

// Проблема: switchFlow не вызывает ре-рендер формы должным образом
// Решение: Добавить key={flow} на форму и явный сброс ошибок

const switchFlow = () => {
  setFlow(isSignUp ? "signIn" : "signUp");
  setError(null);
  setPassword("");
  setShowPassword(false);
};

// В JSX:
<form 
  key={flow} // 👈 Принудительный ре-маунт формы при смене режима
  onSubmit={handleSubmit} 
  className="space-y-4"
>
  {/* ... */}
  <button type="submit">
    {isSignUp ? t.auth.signUp : t.auth.signIn} {/* 👈 Правильный текст */}
  </button>
</form>
```
